## 1. Что сейчас делает бот

Бот выполняет две основные задачи:
- ведет пользователя по воронке подключения к Paradox Bot или команде Paradox(ссылки пока нет на чат под команду, дефолтную поставил);
- дает админам инструменты для рассылок и запуска тестовых торговых сессий в сигнальный канал(текущий канал вроде пока тестовый, его Дима создал, мб потом другой будет, там саму рассылку несложно перенаправить будет).

Mini App открывается только после выдачи доступа. До этого пользователь проходит регистрацию, отправляет Trader ID и подтверждает пополнение.

## 2. Входные ссылки

Есть две основные ветки:

```text
BOT:  https://t.me/paradox_fx_bot?start=want_bot
TEAM: https://t.me/paradox_fx_bot?start=want_team
```

Есть языковые варианты:

```text
BOT RU:  https://t.me/paradox_fx_bot?start=want_bot_ru
BOT EN:  https://t.me/paradox_fx_bot?start=want_bot_en
TEAM RU: https://t.me/paradox_fx_bot?start=want_team_ru
TEAM EN: https://t.me/paradox_fx_bot?start=want_team_en
```

`want_bot` и `want_team` определяют язык автоматически по Telegram `language_code`, если пользователь не пришел по ссылке с явным языком.

## 3. Воронка BOT

Путь пользователя:

1. Пользователь открывает deep link `want_bot`.
2. Бот отправляет стартовое сообщение Paradox Bot.
3. Пользователь нажимает `ХОЧУ БОТА`.
4. Бот отправляет шаг регистрации.
5. Пользователь открывает реферальную ссылку для России или других стран.
6. После регистрации пользователь отправляет Trader ID.
7. Бот проверяет Trader ID через партнерское API Pocket Option.
8. Если ID подтвержден, бот просит подтвердить пополнение.
9. После успешной проверки пополнения бот выдает доступ к Mini App.

Trader ID принимается в форматах:

```text
123456
ID123456
ID 123456
id123456
id 123456
```

Если аккаунт не найден по партнерской ссылке, пользователь получает отдельную ошибку. Если API временно недоступно, бот не пишет "аккаунт не найден", а отправляет техническое сообщение о недоступности проверки.

## 4. Воронка TEAM

Путь похожий, но старт и финал отличаются:

1. Пользователь открывает deep link `want_team`.
2. Бот отправляет стартовое сообщение команды.
3. Пользователь нажимает `ВСТУПИТЬ В КОМАНДУ`.
4. Дальше используется общий путь проверки Trader ID и пополнения.
5. После успешного пополнения бот выдает доступ к Paradox Bot и VIP-группе.

Общие состояния для BOT и TEAM:

- запрос Trader ID;
- ошибка формата Trader ID;
- аккаунт не найден;
- Trader ID подтвержден;
- сумма недостаточна;
- пополнение пока не найдено;
- напоминание 3;
- проверка пополнения.

## 5. Тестовый код доступа

Также сейчас задается переменная:

```text
TELEGRAM_FUNNEL_TEST_ACCESS_CODE=tobi
```

Если отправить это слово боту, пользователь получает доступ без прохождения реальной проверки Trader ID и пополнения. Это нужно только для тестирования и админов.

## 6. Напоминания

Правила:

- при переходе пользователя в новый узел старые задачи завершенного узла отменяются;
- при повторе удаляется только последнее сервисное сообщение этого узла;
- сообщения пользователя и сообщения других состояний не удаляются;
- после подтверждения Trader ID останавливаются напоминания, связанные с ожиданием ID;
- после подтверждения пополнения останавливаются напоминания про пополнение;
- после выдачи доступа старые сервисные сообщения больше не повторяются.

Команды админа нужно писать в личный чат с ботом.

## 7. Админ-команды

```text
/admin
```

Показывает список команд и краткую статистику пользователей в базе.

```text
/segments
```

Показывает доступные сегменты и количество пользователей в каждом сегменте.

```text
/broadcast <HTML-текст>
```

Отправляет HTML-текст всем пользователям.

Пример:

```html
/broadcast <b>Привет!</b>

Это тестовая рассылка.
```

```text
/broadcast
```

Если команда отправлена ответом на сообщение, бот скопирует это сообщение всем пользователям. Это удобно для сообщений с медиа, форматированием и premium emoji. Для меня самый просто способ, так как не надо html писать, а просто собрать сообщение и отправить боту, потом нажать ответить на это сообщение и ввести эту команду

```text
/broadcast_segment <segment> <HTML-текст>
```

Отправляет HTML-текст по выбранному сегменту.

Пример:

```html
/broadcast_segment need_topup <b>Напоминание</b>

Проверь пополнение и нажми кнопку проверки.
```

```text
/broadcast_segment <segment>
```

Если команда отправлена ответом на сообщение, бот скопирует это сообщение пользователям из выбранного сегмента. Принцип такой же как выше расписал для /broadcast, просто заточенность на конкретный сегмент.

```text
/broadcast_test <HTML-текст>
```

Отправляет тестовое сообщение только самому админу.

```text
/signal_mvp
```

Открывает запуск сигнала в канал.

```text
/signal_mvp now
```

То же самое, но старт сессии будет через 15 секунд. Это удобно для быстрой проверки воркера и публикации сообщений.

```text
/signal_sessions
```

Показывает запланированные и активные торговые сессии. В ответе будет ID сессии, статус, окно по МСК и текущая статистика.

```text
/signal_cancel <ID>
```

Отменяет заранее запланированную сессию до ее старта. Работает только для статуса `scheduled`.

```text
/signal_stop <ID>
```

Останавливает уже активную сессию. Работает только для статуса `running`. После остановки бот отменяет открытые jobs этой сессии, поэтому новые сигналы, перекрытия и финальное сервисное сообщение по ней не должны выходить.

## 8. Сегменты для рассылок

Основные сегменты:

```text
all - все пользователи
bot - ветка получения бота
team - ветка команды
no_access - доступ еще не выдан
access - доступ уже выдан
need_id - ждем Trader ID
need_topup - Trader ID есть, ждем пополнение
bot_need_id - ждем Trader ID по ветке BOT
team_need_id - ждем Trader ID по ветке TEAM
bot_need_topup - ждем пополнение по ветке BOT
team_need_topup - ждем пополнение по ветке TEAM
```

## 9. HTML и premium emoji

Все HTML-рассылки отправляются с `parse_mode=HTML`.

Поддерживаются стандартные теги Telegram:

```html
<b>жирный</b>
<i>курсив</i>
<u>подчеркнутый</u>
<s>зачеркнутый</s>
<a href="https://example.com">ссылка</a>
<blockquote>цитата</blockquote>
```

Premium emoji можно вставлять через HTML:

```html
<tg-emoji emoji-id="5321095945780209338">👋</tg-emoji>
```

ID premium emoji можно получать через специального бота для custom emoji ID, например через `@userinfobot`-подобный инструмент, который показывает `custom_emoji_id`.

Самый надежный способ сохранить сложное форматирование, медиа и premium emoji - отправить готовое сообщение админу в чат с ботом, а затем ответить на него командой:

```text
/broadcast
```

или:

```text
/broadcast_segment segment
```

В этом режиме бот использует копирование сообщения, а не пересборку HTML вручную.

## 10. Сигнальный канал

Бот должен быть админом в этом канале и иметь право отправлять сообщения.

MVP-сценарий сейчас работает так:

1. Админ пишет `/signal_mvp`.
2. Бот показывает выбор торговой пары.
3. Админ выбирает экспирацию.
4. Бот делает запрос в Devsbite API.
5. Бот показывает предпросмотр:
   - пару;
   - экспирацию;
   - цену входа;
   - API signal;
   - API confidence;
   - источник решения;
   - причину решения;
6. Админ нажимает `Подтвердить отправку`.
7. Бот создает торговую сессию и отложенные jobs в базе.
8. Воркер публикует сообщения в сигнальный канал по расписанию.

Если данные Devsbite не подходят, админ нажимает `⬅️ Назад к выбору пар` и выбирает другую пару.

## 11. Что публикуется в канал

Cессия публикует цепочку сообщений:

- анонс торговой сессии;
- предупреждение за 60 секунд до входа;
- сам сигнал BUY/SELL;
- результат сигнала;
- перекрытия, если первый вход закрылся в минус;
- финал торговой сессии со статистикой.

Для сообщений с результатом формируется изображение сделки с графиком и данными входа/закрытия.
